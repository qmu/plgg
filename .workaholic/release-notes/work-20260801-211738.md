# Adopt npm workspaces for the monorepo

## Summary

The monorepo installs with one `npm install` instead of 39. The evaluation this
ticket asked for came out *adopt*, and since the spike had to be real to be
measurable, the spike is the adoption: a root `package.json` declaring
`workspaces: ["packages/*"]`, `scripts/npm-install.sh` collapsed to a single
command, and five hard-coded install-layout paths corrected.

## Key Changes

- Measured on the same machine with a warm cache: first install **22.40 s →
  4.60 s**, re-install **0.94 s**, `node_modules` on disk **1.4 G → 403 M**,
  lockfiles **39 → 1**.
- The empty-`.bin` failure the `file:` layout guaranteed some of the time — a
  tree that looks installed and fails with `plgg-bundle: command not found` — is
  structurally gone: every workspace binary lands once in the root
  `node_modules/.bin`.
- The five things adoption broke were all the same mistake: encoding *where* the
  installer had put something instead of asking for it by name.

## Changes

### Added

- Root `package.json` (private, `workspaces: ["packages/*"]`) and one lockfile.
- `docs/npm-workspaces-decision.md` — the decision with its measurements.

### Changed

- `scripts/npm-install.sh` — one root install.
- `scripts/typecheck.ts` imports `typescript` by bare specifier;
  `scripts/check-all.sh`, `scripts/build.sh` and
  `scripts/gate-vendor-boundary.sh` resolve it from the root; and
  `scripts/tsconfig.json` drops its pinned `typeRoots` for tsc's default upward
  walk. Each spelling is correct under either layout.

## Notes

The `file:../` specifiers in every package.json are unchanged — npm resolves a
`file:` dependency naming a workspace member to that member, so they still
document the dependency graph and `build.sh` still orders builds by it.

Known consequence, accepted: `scripts/*.ts` now emit
`MODULE_TYPELESS_PACKAGE_JSON` warnings, because the root manifest is their
nearest one and declares no `"type"`. Adding one there would change how every
package lacking its own type is interpreted, so it is deliberately not done; the
decision doc names the real fix as its own ticket.

Existing checkouts can delete their stale `packages/*/node_modules` to reclaim
about 1 G.
