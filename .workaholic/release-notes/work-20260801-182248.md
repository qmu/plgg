# Retire relocate.mjs in the last three bin consumers

## Summary

The `relocate.mjs` `/tmp` copy-and-re-exec hack is gone from the monorepo. Three
packages each shipped a verbatim copy of a 118-line helper that copied the whole
installed package out of `node_modules` and re-executed it there, because Node
refuses to strip types from a `.ts` under `node_modules`. `plgg-bundle` retired
its copy earlier by shipping a compiled `dist/cli.es.js`; this retires the last
three — and only two of them needed that answer.

## Key Changes

- `plggpress` and `plgg-cms` now run a compiled `dist/cli.es.js` in a real
  registry install, and their `.ts` source in the monorepo.
- `plgg-test` needed only its resolver hook compiled (`dist/hook.es.js`): the
  hook already transpiles `.ts` itself, so it was the one file that could not go
  through the hook.
- The publish install smoke checked `import` **or** `bin`, never both — so the
  three packages that publish both surfaces had their launchers smoked by
  nothing. Both are now checked.

## Changes

### Removed

- `packages/plgg-test/bin/relocate.mjs`,
  `packages/plggpress/bin/relocate.mjs`,
  `packages/plgg-cms/bin/relocate.mjs` — and with them the
  `/tmp/plgg-relocate-*` cache, which no plgg CLI creates or reads any more.

### Changed

- `plggpress` and `plgg-cms` bundle configs gain a `cli` entry; their bins pick
  the compiled CLI by package realpath.
- `plgg-test`'s bundle config gains a `hook` entry; `src/Resolve/register.mjs`
  registers the compiled hook under `node_modules` and the source in the
  monorepo.
- `scripts/publish.ts` smokes both the importable surface and the bin when a
  package declares both.

## Notes

Verified in a registry-shaped install per package: `plggpress --help` and
`plgg-cms --help` run clean, and the installed `plgg-test` ran a purpose-built
target package's specs and its `--coverage` gate — exercising self-alias,
cross-package bare and relative `.js`→`.ts` resolution through the compiled
hook. No `/tmp/plgg-relocate-*` directory appears.

Resolves the July concern about the stale bin cache by construction: there is no
cache left to go stale.
