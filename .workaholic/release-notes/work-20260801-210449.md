# Export every plggmatic class hook and gate the example app

## Summary

Every class hook plggmatic emits is now a named export, and the framework's own
demo app is under the gate that forbids typing one. The exemption that sat in
`scripts/gate-framework-names.sh` is deleted rather than widened — it existed
because the framework was incomplete, and completing it was the work.

## Key Changes

- `Meta/model/classHooks.ts` is the single definition site for all ~55 hooks,
  plus `cssVar`/`cssVarRef` for the `--pm-*` custom properties and `selector()`
  for writing a hook as a CSS rule.
- The emitters import those constants instead of composing `${cssPrefix}-…`
  inline, so "the framework renders it" and "the framework guarantees it" became
  one fact.
- `packages/plggmatic-example/src` joins the gate's `CONSUMERS`; its 84 typed
  `pm-` literals across 14 files are gone.

## Changes

### Added

- ~60 named exports on the plggmatic root: every component, layout, form,
  renderer and breadcrumb hook, `toastToneClass(tone)`, and the
  `cssVar`/`cssVarRef`/`selector` helpers.

### Changed

- `rowClass`/`colClass`/`paneClass` and `themeToggleClass`/`sunClass`/`moonClass`
  now re-export from the single definition site rather than deriving their own
  copy — same values, one definition each.
- `scripts/gate-framework-names.sh` covers the example app, with no exemption
  left in the file.

## Notes

The rename-safety property was demonstrated rather than asserted: with
`cssPrefix` set to `zz` and plggmatic's dist rebuilt, the example rendered
`zz-board`, `.zz-board` and `var(--zz-surface)` with all 57 of its tests still
passing and not one file edited.

Purely additive for consumers — no existing export changed signature or value,
and the rendered DOM is byte-identical.
