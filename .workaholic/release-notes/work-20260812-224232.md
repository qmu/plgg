# Migrate the toolchain to TypeScript 7 via split-version etc

## Summary

The TypeScript toolchain moves to 7.0.2 (Go-native compiler): root + 27 manifests on TS7, while plgg-bundle and plgg-test — whose runtime dependencies ship to npm users and rely on APIs TS7 removed — deliberately stay on TS6. All gates green; test counts identical.

## Key Changes

- Split-version layout: root + 27 manifests on `typescript@^7.0.2`, TS6 nested under the 2 publishing packages — hoist made deterministic by an explicit root declaration
- Typecheck gate redesigned from the removed incremental compiler API to per-package native `tsc` processes (cold run 21.4s → 11.4s flat)
- The native-binary tradeoff recorded with measurements in plgg-bundle's DEPENDENCY-LOG (build 89.0s → 59.0s, check-all 121.3s → 127.1s)

## Changes

### Added

- TS7 API gap map with evidence (docs/typescript-7-api-gap.md): transpileModule/preProcessFile absent from every adoptable 7.x, scanner PoC, 28/29 tsconfig reproduction
- TS7 adoption tradeoff record in packages/plgg-bundle/DEPENDENCY-LOG.md — two decisions (toolchain adoption with numbers; TS6 pin as accepted risk with exit strategy)

### Changed

- 27 package manifests + workspace root to `typescript@^7.0.2`; lockfile pins all 20 platform nodes with resolved+integrity; TS6 nested under plgg-bundle/plgg-test
- scripts/typecheck.ts spawns each package's own declared `tsc` (TS7 native / nested TS6) in a bounded pool with `--jobs`; runTests caps the gate's compiler concurrency
- Stale typecheck-gate descriptions corrected in CLAUDE.md, check-all.sh, and plgg-test's README; dependabot PR #112 closed as superseded
