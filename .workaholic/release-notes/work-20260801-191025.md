# Add GCP service-account OAuth token exchange to plgg-fetch

## Summary

plgg-fetch can now turn a GCP service account into an access token. The
JWT-bearer flow — build the claims, sign the assertion RS256, POST it to
Google's token endpoint — is a domain module over the package's Web Crypto seam,
and the exchange rides this package's own `post` + `decodeJsonBody`. No vendor
SDK, no new dependency, and no raw `fetch` anywhere in it.

With the AWS SigV4 sibling released alongside it, both crypto-bearing auth
families deferred out of the transport-core ticket are now in.

## Key Changes

- RS256 is verified against Node's `crypto` — an implementation independent of
  the Web Crypto path under test — over a key pair generated fresh per run, so
  no private key is committed anywhere.
- The claims JSON is written explicitly rather than through `encodeJson`: a JWT
  signature covers bytes, so the key order is pinned by the code, and the
  serializer's `Result` would have threaded an unreachable error arm through the
  signing path.
- A hard secret finding on the production vendor file was fixed at the source
  rather than allowlisted; only the spec, which cannot avoid the OAuth wire
  vocabulary, is declared.

## Changes

### Added

- `gcpAccessToken(account, request, issuedAtSeconds)` — claims, RS256
  assertion, and token exchange in one call.
- `gcpBearerAuth(token)` — the obtained token as an `Authorization` header.
- The individually-exported steps: `gcpJwtClaims`, `gcpClaimsJson`,
  `gcpSigningInput`, `gcpAssertion`, `gcpExchangeAssertion`.
- `rs256Sign`, `toBase64Url`, `textToBase64Url`, `pemToDer` on the shared
  `src/vendors/webcrypto.ts` seam, beside SigV4's `sha256Hex`/`hmacSha256`.

## Notes

`issuedAtSeconds` is a parameter rather than a clock read inside the helper, so
every step below the transport is a pure function of its inputs — which is what
lets a test pin the exact second and compare a whole signing input.

Package coverage: 100% statements / 100% lines / 97.22% branches / 97.59%
functions against a 91% gate; 88 plgg-fetch tests pass with both signing
families on the merged seam.
