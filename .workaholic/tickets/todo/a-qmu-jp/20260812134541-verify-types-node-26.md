# `@types/node` 26 を検証して取り込む（dependabot PR #113）

## Overview

dependabot が `@types/node` を 25.9.5 → **26.2.0** に上げる PR #113 を開いている。
29 のパッケージ manifest（`^25.6.0` → `^26.x`）とルートの `package-lock.json` を
書き換える、**型定義だけの変更**である。

この PR は、`.github/dependabot.yml` を `/packages/*` からワークスペースルート
`/` に向け直した直後に開いた最初の更新 PR の 1 つで、**設定変更が実際に機能して
いることの実証**でもある（それまでは凍った per-package lockfile にしか向かなかった）。

同時に開いている PR #112（typescript 7）とは**性質がまったく違う**。あちらは
コンパイラ本体の Go 移植で API と配布形態が変わるため、別途ミッションとして
扱う。この 2 つを混ぜないこと。

## Policies

- `workaholic:implementation` / `policies/coding-standards.md` — 型の保証が
  `as` / `any` / `ts-ignore` で溶けないことが前提。型定義のメジャー更新は、
  その保証の土台が動くということなので、**通ったかどうかを型チェックで示す**。
- `workaholic:operation` / `policies/ci-cd.md` — 「緑になった」ではなく「何を
  検査したか」。型定義変更の場合、`node scripts/typecheck.ts`（全パッケージを
  1 つの型グラフで検査）が緑であることは、そのまま十分な証拠になる。
- `workaholic:design` / `policies/vendor-neutrality.md` — 新しい依存は増えない
  （既存の型定義パッケージのバージョンが上がるだけ）。
- `.workaholic/constraints/project.md` の Dependency Currency — dependabot PR は
  30 日以内に「マージするか、明示的に拒否する」。放置が禁じられている。

## Key Files

- 29 の `packages/*/package.json` — `"@types/node": "^25.6.0"` を宣言している。
  PR #113 が全部書き換える（手で編集する必要はない）。
- `package-lock.json` — ルートの唯一の lockfile。
- `.github/workflows/run-tests.yml` / `deploy-guide.yml` — **CI は Node 22.x**。
- 各パッケージの `engines` — `"node": ">=22.6"` を宣言しているものがある。
- `scripts/typecheck.ts` — 全パッケージを 1 つの型グラフで検査する本命のゲート。
  型定義の更新で壊れるならここに出る。

## Implementation Steps

1. PR #113 のブランチを取り込むか、同じ変更を自分で行う（29 manifest の
   `^25.6.0` → PR が使っている範囲、＋ルート lockfile 再生成）。
2. `./scripts/npm-install.sh` を実行し、ルート lockfile に `@types/node` の
   26 系だけが入り、他のパッケージが動いていないことを確認する。
3. `node scripts/typecheck.ts` を実行する。**新しい型エラーが出た場合、
   `as` / `any` / `ts-ignore` で黙らせてはならない** — 型を絞るか、実際の
   API の使い方を直す。エラーが構造的で大きい場合は、そこで止めて報告する。
4. `./scripts/check-all.sh` を通す。

## Quality Gate

**Acceptance criteria**

- `git grep -c '"@types/node": "\^25' packages/*/package.json` が **0**
  （25 系の宣言が残っていない）。
- ルート lockfile の `node_modules/@types/node` が 26 系。
- `node scripts/typecheck.ts` が全パッケージ clean。
- `./scripts/check-all.sh` が緑（exit 0）。
- 新規コードに `as` / `any` / `ts-ignore` が**増えていない**:
  `git diff origin/main..HEAD -- '*.ts' | grep -E '^\+.*(\bas\b|: any|ts-ignore)'`
  が空であること（型エラーを逃げで潰していないことの機械的証明）。
- `npm audit` が 0 vulnerabilities のまま。

**Verification method**

- 上記をそのままコマンドとして実行し、出力を Final Report に貼る。
- 型エラーが 1 件でも出た場合は、**何がどう変わったのか**（どの Node API の
  型が変わったか）を報告に書く。黙って直さない。

**Gate**

- check-all 緑、かつ typecheck clean、かつ escape-hatch の増加ゼロ。

`Decided:` **CI の Node は 22.x のまま上げない。** `@types/node` 26 は Node 26 の
型を記述するので、**実行環境より新しい型**を使うことになる。これは型定義更新では
普通のことだが、リスクは「Node 26 にしか無い API を型が許してしまう」点にある。
Node のランタイム更新は別の判断なので、このチケットでは触らない（`/drive` で
開発者が上書き可）。

`Decided:` **型エラーが構造的に大きければ、潰さず止めて報告する。** 型定義の
メジャー更新で大量のエラーが出るなら、それは「直す作業」ではなく「判断が要る
作業」であり、無人で押し切る対象ではない（`/drive` で開発者が上書き可）。

`Decided:` **PR #112（typescript 7）はこのチケットの射程外。** 同じ日に開いた
dependabot PR だが、あちらはコンパイラ本体の Go 移植で、ネイティブバイナリ 20 個と
API の移動を伴う。別ミッションで扱う（`/drive` で開発者が上書き可）。

## Considerations

- **実行環境より新しい型を使う状態になる。** CI は Node 22.x、ローカルは 24.x、
  型は 26 系。`@types/node` が Node 26 で追加された API を型として提供すると、
  コンパイルは通るのに実行時に存在しない、という組み合わせが理屈上は作れる。
  今のコードがそれを踏む可能性は低いが、**踏んだときに型が守ってくれない**という
  ことは記録しておく価値がある。将来 Node ランタイムを上げるチケットと対で
  考えるのが本来の形。
- **`engines` の `>=22.6` は変えない。** 型定義の更新は実行要件を変えない。
- **この PR は dependabot 設定修正の実証でもある。** マージするにせよ拒否する
  にせよ、「ルートの lockfile を対象にした更新 PR が実際に届いた」という事実は
  Final Report に残す価値がある（ローカルでは検証できないと concern に
  記録されていた点が、これで閉じる）。
