## 1. Overview

The plggmatic reference exhibit (demo1, the contract-development business-management app) is now served from the guide's own domain instead of only from a developer-host dev tunnel. The guide build gained a post-build step, `packages/guide/nest-exhibit.ts`, that copies `packages/plggmatic-example/dist` under the guide's `dist/plggmatic-reference/`, so the single existing publisher — the assets-only Cloudflare Worker deployed by `deploy-guide.yml` on merge to main — serves it at `plgg.qmu.co.jp/plggmatic-reference/demo1.html`.

**Highlights:**

1. `nest-exhibit.ts` nests the built exhibit after `plggpress build` — the ordering is load-bearing, because plggpress rm -rf's the outDir before writing.
2. `deploy-guide.yml` now runs `npm run build --prefix packages/guide` instead of an inline `npx plggpress build`, closing the last second-copy of the build topology in the workflow.
3. The landing page's `<https://…>` pseudo-autolinks, which plgg-md rendered as escaped literal text on the live site, became a real markdown link plus inline-code dev URLs.

## 2. Motivation

The guide's landing page advertised the plggmatic reference, but neither half of that advertisement worked. The exhibit itself lived only behind the `qmu-dev` cloudflared tunnel at `plggmatic-reference.qmu.dev`, a surface that is down whenever the developer's dev server is not running — and it was down. The links pointing at it were written as `<https://…>` autolinks, a syntax plgg-md's inline scanner has no branch for, so the published page showed escaped literal text rather than anything clickable.

This lands directly on top of the 2026-08-18 `deliver-the-guide-from-cloudflare-workers-with-a-staging-surface` mission, which cut the guide over to an assets-only Cloudflare Worker with auto-deploy on merge as the site's single publisher. That mission left the guide as a pure plggpress tree ("40 HTML files and nothing else") and left the exhibit on the dev tunnel; this branch is the first to nest a second static subtree into that Worker's dist, correcting the now-false invariant in the same change.

## 3. Changes

### 3-1. Serve the plggmatic exhibit on plgg.qmu.co.jp ([2619dc3d](https://github.com/qmu/plgg/commit/2619dc3d))

Added `packages/guide/nest-exhibit.ts` (post-build copy of the exhibit dist into `dist/plggmatic-reference/`, failing loudly on a missing or short copy), chained it into the guide's `build` script, switched `deploy-guide.yml` to that script, repointed `index.md` at the on-domain exhibit with a real link, and corrected the three comments the change falsified.

## 4. Outcome

`npm run build --prefix packages/guide` produces 40 pages plus a 10-file `dist/plggmatic-reference/`; `dist/index.html` carries a real `<a href="/plggmatic-reference/demo1.html">` with zero escaped-URL remnants, and the nested `demo1.html` is stamped `./demo1.js?v=92f45831`. `./scripts/check-all.sh` is green across 30 checks and the dead-link gate passes with no `linkIgnore` addition. Publication is automatic on merge; the live-URL probe is the one remaining acceptance step (ticket `20260828114602`).

## 5. Concerns

### The guide build is outside check-all, and nest-exhibit.ts is outside the typecheck gate

- **Severity:** moderate
- **Description:** `nest-exhibit.ts` sits deliberately outside `packages/guide/tsconfig.json`'s scope, so `node scripts/typecheck.ts` never sees it, and `./scripts/check-all.sh` does not run the guide build; the only exerciser is `npm run build --prefix packages/guide`, whose first unattended execution is inside the deploy workflow, after the merge (see [2619dc3d](https://github.com/qmu/plgg/commit/2619dc3d) in `packages/guide/nest-exhibit.ts`)
- **How to Fix:** Add the guide build to check-all, or bring `nest-exhibit.ts` and `site.config.ts` into a small tooling tsconfig so the typecheck gate covers them without widening the Worker program's scope.

### The exhibit-completeness guard is a magic-number floor, not a manifest

- **Severity:** low
- **Description:** `nest-exhibit.ts` fails when fewer than 10 files land in the target — a snapshot of the exhibit's five pages and five bundles that nothing keeps in sync with the exhibit itself (see [2619dc3d](https://github.com/qmu/plgg/commit/2619dc3d) in `packages/guide/nest-exhibit.ts`)
- **How to Fix:** Assert the copy against its source — compare source and target file counts and require the five known page names — so the guard tracks the exhibit rather than a snapshot of it.

### Acceptance completes only after the merge publishes production

- **Severity:** low
- **Description:** `deploy-guide.yml` triggers on push to main, so the CI path that builds and nests the exhibit cannot be exercised before the merge; the pre-merge proof is the local build plus dist assertions (see [2619dc3d](https://github.com/qmu/plgg/commit/2619dc3d) in `.github/workflows/deploy-guide.yml`)
- **How to Fix:** Run the post-release probes immediately after the merge; if the nesting step fails on the runner, revert this commit to restore an exhibit-free but otherwise working guide.

### The autolink renderer gap is fixed at two call sites, not by a gate

- **Severity:** low
- **Description:** The two `<https://…>` pseudo-autolinks are rewritten, but nothing stops the next guide author from writing the same syntax and shipping the same escaped output — the dead-link checker sees no link at all (see [2619dc3d](https://github.com/qmu/plgg/commit/2619dc3d) in `packages/guide/index.md`)
- **How to Fix:** Queued ticket `20260828114603-add-gfm-autolink-support-to-plgg-md.md` adds real GFM autolink support to plgg-md, removing the class rather than the two instances.

## 6. Successful Development Patterns

- Delete the second copy rather than update it: the workflow's inline `npx plggpress build` became the repository's own npm script, so CI runs exactly the command a developer runs.
- Fail loudly instead of shipping an empty surface: `nest-exhibit.ts` exits non-zero on a missing or short copy rather than publishing a hollow `/plggmatic-reference/`.
- Correct falsified comments in the commit that falsifies them: the `/example/` nesting claim and the "40 HTML files" invariant were fixed alongside the change that made them untrue.
