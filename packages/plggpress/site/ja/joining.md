# 二つのサイトを列でつなぐ

手引きから別サイトのカタログを開く場合を考えます。手引き側は `partners` にカタログのオリジンを、カタログ側は `embedders` に手引きのオリジンを登録します。逆向きにも開くなら、それぞれで両方を設定します。

次の定義を手引き側の設定ファイルに置き、ホスト名を実際の値に置き換えます。デフォルトエクスポートするオブジェクトに `...connections` を加えてください。`frames` はサイトが別途フレームに表示するウィジェット用です。ここへの登録だけでは、ウィジェットへのリンクを列として開けるようにはなりません。

```ts
const connections = {
  partners: ["https://catalog.example.com"],
  embedders: ["https://catalog.example.com"],
  frames: ["https://widgets.example.com"],
};
```

各項目には `https://` とホスト名（必要ならポート）を指定し、末尾のスラッシュ、パス、ワイルドカードは付けません。開発時の `localhost` と `127.0.0.1` には HTTP も使えます。設定を変えたら両サイトを再ビルドし、[配信時のヘッダー](/operations/)を反映します。

## 読者から見える動作

本文にカタログのページへの通常のリンクを書くだけです。開いた列には相手のタイトルとホスト名が表示されます。その中のリンクも、元のサイトか許可した相手を指していれば隣に開けます。明暗の切り替えは列にも伝わり、相手の列で横スクロールすると隣の列に移れます。4 秒以内に相手が応答しなければ、その列には読者が直接開けるリンクが残ります。

## ブラウザーが守る境界

相手の HTML は相手のオリジンの sandbox 付き iframe に表示します。相手は親ページの本文を書き換えたり、親ページを別の場所へ移動したりできません。列を開く要求は、登録したオリジンから、その相手のために作ったフレームを通して届いた場合だけ受け付けます。共有 URL に知らないホストを書いても許可先は増えません。自サイトの列は同一オリジンの HTML だけを読み込み、ブラウザーは URL の `c` から最大 12 件を復元します。

`partners` を設定すると、ページの `frame-src` がフレームの行き先を自サイト・相手・`frames` の一覧に制限し、許可外へのリダイレクトも防ぎます。逆に「誰がこのページを囲めるか」は配信側の `frame-ancestors` ヘッダーで制御します。相手の列に何を掲載するかは相手の運営者が決めます。
